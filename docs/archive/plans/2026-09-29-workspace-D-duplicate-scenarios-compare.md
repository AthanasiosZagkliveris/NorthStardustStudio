## D1. Duplicate organization
On the organizations (Landing) screen, each organization gets a **Duplicate** action beside its × (same style as other row actions): creates "Copy of <name>" directly below it with new organization id and fresh ids where ids must be unique across organizations; all Systems' answers, annotations and images copied; "last worked" cleared. Opens nothing automatically. Undo toast (C1) for accidental duplicates is not needed — the copy can be removed with × (which already has undo). Respect localStorage quota: if the copy would exceed it, show the store's clear error and don't create a partial copy. Tests.

## D2. Duplicate a card
A **Duplicate** icon button next to the × in the shared card head (tooltip/aria "Duplicate <thing>") for cards whose copy makes sense: Segments, Customer Profiles, Competitors, Offerings, funding sources, Goals, Objectives, Metrics, Activities, Resources, cost lines added by the user. The copy is inserted right after the original, named "<name> (copy)", opened (unfolded) with its name field focused and selected; its own nested content is copied with new ids (a Segment's profiles/competitors/offerings; an Objective's initiatives/metrics); references FROM other pages to the original are NOT duplicated (e.g. an Offering's revenue stream on Sustainability) — instead, where the other page lists items by the original (e.g. streams per Offering), the copy simply appears there empty like any new item. Annotations are not copied. Tests (ids unique, nested copied, references untouched, focus).

## D3. Scenarios (financial "what ifs")
- **Model:** per organization, `scenarios: { id, name, overrides: Record<fieldKey, value>, createdAt }[]` (max 3 scenarios besides the Current plan), stored with the organization (format version 2 readers ignore unknown data — confirm; bump only if needed). `fieldKey` = a stable path to an answer value (System, section, answer path/ids). Only these inputs are scenario-able (define them in one table in one module, easy to extend): plan start and length; each Offering's price and pricing model (Sustainability/revenue); demand and conversion inputs (Customer Engagement › Demand & Conversion); each cost line's amount and timing; each funding source's amount, status, and loan terms (rate, payments, start); founders' pay. Everything else is shared and not editable per scenario (fields show as normal but disabled with a quiet note "Shared by all scenarios" only while a scenario is active).
- **Selector:** on Business › 2. Customer Engagement, 4. Financial Foundation and 5. Sustainability, a compact selector in the page's header line (right side, same style as the app's small selects): "Current plan ▾" listing the scenarios, "+ New scenario…" (asks for a name in a small inline field; starts as an exact copy = no overrides), and "Compare…" (D4). Max three options visible logic: when 3 scenarios exist, "+ New scenario" is disabled with the reason.
- **Editing in a scenario:** the page shows the scenario's values (Current plan + overrides). Editing a scenario-able field writes an override; such fields show a small "Changed in <Scenario>" marker with a "Reset" (removes the override). The page header shows a subtle band "Viewing scenario: Cautious — changes here don't affect the Current plan." in the accent colour family (all themes). Every calculated panel on these pages (Funding Need, Financial Position, signals, Sustainability charts, Stress Test) uses the scenario's values. Leaving the Business System returns to the Current plan (the selector remembers nothing between visits — avoids accidental edits).
- **Scenario menu actions** (in the selector, for the active scenario): **Rename**, **Make this the plan** (adopts: the scenario's overrides are applied to the Current plan; the replaced Current values are kept as a new scenario named "Plan before <date>" so nothing is lost — this counts toward the 3 max; if full, ask to remove one first), **Delete** (with the undo toast).
- **Documents, Review, status, search:** always use the Current plan. The Business Documents page shows a quiet line when scenarios exist: "Documents use the Current plan. Compare scenarios →".
- Use the existing what-if mechanism (`withWhatIf` in FinancialModel, the Stress Test) where it fits rather than a second calculation path.
- Tests: override resolution, editing/reset, calculations per scenario, adopt with the "Plan before" safety copy, delete/undo, persistence/export/import.

## D4. Compare
- **Entry:** "Compare…" in the scenario selector, and a **Compare** item on the organizations screen (when ≥2 organizations). Route `/compare`, page title "Compare", same header/themes; Escape goes back.
- **Choose:** up to three columns of the same kind — either scenarios of the current organization (Current plan + scenarios; preselect all, max 3 columns) or organizations (pick 2–3).
- **Rows, outcome figures first:** break-even month; funding need; funding gap; lowest cash and its month; runway / months of cash; revenue and profit (before tax) per plan year; total loan repayments and interest; for organizations additionally legal form, main Segment, number of Offerings. Then **Inputs**: every scenario-able input (scenarios) or headline answers (organizations). **"Show only differences"** on by default; differing cells highlighted by shape/weight + colour (not colour alone); the best value per outcome row marked with a small "best" tag where "best" is unambiguous (earlier break-even, smaller gap, higher lowest cash, higher profit) — no tag for neutral rows.
- **Column actions:** scenario → **Make this the plan** (same as D3); organization → **Open**. Nothing editable in Compare.
- Wide tables scroll inside their own container; the first column (row labels) sticky; at 768 the table scrolls horizontally with the sticky label column. No overflow.
- Tests: metrics per column from the model, differences filter, best-tag rules, actions.
