# The standard of the documents

Status: **rules**, written 2026-10-29. How a document in `docs/` is named, numbered, headed, written and kept. The check `npm run docs:standard` enforces the parts that can be checked (marked **checked**). The contents of the documents are in `README.md`; the alphabetical index is `index.md`.

## 1. Where a document goes

| Folder | Holds | Naming |
|---|---|---|
| `docs/app/` | The app: contents, index of its places, glossary | plain names |
| `docs/design/core/` | The current design of the Foundation, the sources, the research, the log, the open list, the generated catalogue (documents 1 to 7) | `NN-name.md` |
| `docs/design/library/` | The assets library, its generated lists and logs (8 to 15) | `NN-name.md` |
| `docs/design/current/` | What the app is today in detail: texts, reactions, components, pop-ups, tooltips, folders, card structure (16 to 26) | `NN-name.md` |
| `docs/design/questionnaire/` | The first version, its future features, the questions, the lists, the research (27 to 35) | `NN-name.md` |
| `docs/ai/` | Rules, references and playbooks for an AI assistant | plain names |
| `docs/specifications/business-system/` | The pages of the Business System | `page-N-name.md` |
| `docs/archive/` | Finished or replaced documents, kept for their information | plain names |

**Numbering** (checked): the design documents are numbered 1 to N in the order of the chapters, with no gap and no repeat. The number is in the file name (two digits), in the title, and it is how documents cite one another ("doc 28"). A new document takes the next number in its chapter; the numbers after it move up and the references are rewritten (the index fails on a gap). A document that leaves the numbered set goes to the archive with a plain name.

## 2. The head of a document

Every document opens with these lines, in this order (checked):

1. **Title**: `# N. Title` for a design document (N is the number of the file; **checked**), `# Title` elsewhere. Sentence case.
2. **Status line**: `Status: **kind**, written YYYY-MM-DD, updated YYYY-MM-DD.` and, after it, one sentence saying what the document holds. The kind is one of the list below; both dates are ISO (checked: the kind and a date).
3. **Generated documents** carry instead (or beside the status) a line that begins "Generated by", names the command and the source, and ends "Do not edit by hand." (checked).
4. **Related line** (optional): `Related: doc N (what), doc M (what).`
5. **Banners** (optional): a block quote `> **Title (owner, date):** text` for a rule that governs the whole document (for example the first-version banner in documents 27 to 32).
6. **Contents block**: a list of the sections with links, when the document is longer than 60 KB or has more than 12 sections.

### The kinds

| Kind | Meaning |
|---|---|
| rules | What must hold; a check enforces most of it |
| reference | How things are, to look up (including source registers) |
| research | What was found, with its sources and how they were weighed |
| collection | The owner's data written down as given, before design |
| current design | What the app is today |
| specification | What a page or the first version asks, shows and contains |
| proposal | A plan or design not (or only partly) built; the status line says what is built |
| living list | An open list: an item leaves it when done and the log records it |
| log | A record of changes, newest on top |
| playbook | A procedure |
| index | A list of documents, places or subjects |
| contents | The contents of a part of the app |
| archive | Finished or replaced; the status line says where its information now lives |
| generated | Written by a script (the kind of a document that has a "Generated by" line) |

## 3. How a document is written

- **Present tense.** A document says what is true now. **A change is written in the log** (`design/core/04-log.md`) and nowhere else: no "since", "was changed on" or round-by-round history in a describing document.
- **One owner for each fact.** A fact is written once, in the document that owns it, and the others point to it ("see doc 21, section 3"). The owner of a topic is named in `index.md`.
- **Sections** of a long document are numbered `## 1.`, `### 1.1`; the numbers do not change once other documents cite them (a section that moves to a new document keeps its numbers, as 5.x did in document 35).
- **Where the code and a document disagree, the code is right** and the document is the one to fix. Names of files, classes, properties and functions in backticks must exist (the document-reference test checks the documents it lists).
- **Plain English**, sentence case headings, ISO dates, "doc N" for a design document and "document N" in running prose; a file is named in backticks with its path from `docs/`.
- **Relative links** between documents are written as Markdown links and must resolve (checked).
- **Decisions** the owner has not made are marked **[D]**; a rule of the first version is marked in place and the rest is a future feature (doc 34).
- **Generated documents** are never edited by hand; the generator and its source are named in the document.

## 4. Each chapter has a README

`docs/design/<chapter>/README.md` is written by `npm run docs:index`: the scope of the chapter, and one row for each document (kind, what it holds, last change). The descriptions are in `tools/scripts/docs/write-index.mjs`, the one place where they are kept; `docs/README.md` and `docs/index.md` are written from the same data.

## 5. Adding a document

1. Pick the chapter and the number (section 1); rename and renumber what follows if needed.
2. Write the head (section 2).
3. Add the document to the list in `tools/scripts/docs/write-index.mjs` with its kind and a one-sentence description; add subjects to `TOPICS` if people will look it up.
4. Run `npm run docs:index` and `npm run docs:check` (it includes `docs:standard`).
5. Write the change in the log.
