# The code map: where things are in `src`

Status: **reference**, written 2026-10-20, updated 2026-11-21. Where things are in `src`: one line for each folder, and the rules for a new file.

One line per folder: what is in it and what is not. A file's name is its component's name (PascalCase for a component, camelCase for a module of functions); a test stands beside what it tests, with the same name and `.test`.

## `src`

| Folder | Holds |
|---|---|
| `components/controls/` | The shared controls, each drawn once and used everywhere: `AddButton`, `BackButton`, `FoldHead`, `NavArrow` (also `vertical`: the 32px square of a row's move), `RadioChoice` (`FittingRadioChoice`, the same with every option as wide as the longest, is in `components/interview/editors/foundation/`), `TitleTooltips` (every tooltip: one place, `tipWords` makes the "Click to ..." sentence), `FunnelButton`, `RemoveButton`, `NumberCell`, `TextBox`, `TextField`, `TickBox`, `TickField`, `FieldLabel`, `PopupPanel` (with `usePopupDismiss`), `Tooltip` (`TooltipBox`, `useAboveTip`); also `ChipOpen`, `ChoiceCard`, `DayButton`, `MenuOption`, `PressRow`, `SuggestionOption`, `TabList`. A new control that more than one place needs goes here. |
| `components/shell/` | What every screen has: the header (`AppHeader`), the footer, the save status, the undo toast, the error boundary and the preferences dialog. |
| `components/menu/` | The Menu (`ToolsMenu`) and the tools it opens: the search (`SearchButton`, `SearchDialog`), Focus (`FocusModeButton`), the Global Settings (`settingsOpen.ts`). |
| `components/calendar/` | The Organisation's calendar (`OrganizationCalendarPanel`, `CalendarFunnel`) and `calendarOpen.ts`, the light helper the Menu opens it with. |
| `components/capabilities/`, `components/systems/` | The lists of Capabilities (and their description dialog and input) and of Systems (`SystemList`, `SystemItem`, the interview's progress and section). |
| `components/workbook/` | The Workbook page's parts: the Review (`OrganizationReview`), the Glossary list, the Business Documents and their forecast table, the tools slot (`WorkbookTools`). |
| `components/references/` | `HarvardReference` draws one Harvard reference. |
| `components/interview/cards/` | The card: `BusinessCard` (in `BusinessCardFields.tsx`, with the shared `OptionalNote`, `BusinessTicks` and `BusinessGroup`), its box (`CardShell`), head (`CardHead`), number (`CardNumber`), name (`NameCell`, `CardNameInput`), the boxes and columns of cards, what a card says folded (`cardSummary`), the cards just made (`freshCards`). |
| `components/interview/tiles/` | The tile and everything that opens from it: `Tile`, `TileGrid`, `TileParts` (the face, the links, the "+", the hover origin), the page tile (`SectionTiles`), the section and category views, the card tile, the dialog's levels, the floating cards and their arrows, the Inventory (`CapabilityOverview`: its table, its filter and sort window, the Tiles / Table and `Aa` radios). |
| `components/interview/fields/` | The cells and what stands around them: the field row and its head (`FieldRow`, `FieldHead`), the field's marks and status, the info note, the dropdown (`OptionPicker`), the date and month (`DateCellInput`, `MonthYearPicker`, `DatePopup`), the colour picker, the lists (`NumberedListInput`, `ListStatic`), the table (`DynamicTable`; its widths and text measuring in `dynamicTableWidths.ts`), the arrows (`FoldArrow` with `variant` card or label, `direction` and `pressed`; `PageArrow`), the text link. |
| `components/interview/editors/` | The editors of the pages and their parts: one `…Editor.tsx` for each page or section (Business Capability, Engagement, Foundation, Financial, Legal Entity, Founders, Brand, Strategy, the Process library (`ProcessLibraryEditor.tsx`, its parts in `ProcessLibraryParts.tsx`, its column widths and row helpers in `processLibraryColumns.ts`); the two Financial pages keep their help texts and formulas in `financialFoundationTexts.ts` and `financialSustainabilityTexts.ts`, the Operational log), the answer renderer, the channel resources. The pure part of a page (its texts, limits and the functions that change its answer) is in `…Model.ts` beside the editor (`BusinessCapabilityModel`, `BusinessEngagementModel`). They are large: a card kind's own code stays with its editor until it is split. |
| `components/interview/rails/` | The navigation rail (the bullets and their page tags). |
| `components/interview/tests/` | The tests that cross several components (a whole card, a page's rules); a test of one component stands beside it. |
| `components/notepad/` | The Notes tool (its header button and the Notes panel, picking a field), the Workbook's header button (the same one on the Landing page) and its Card Notes (`WorkbookCardNotes`, on the Workbook page), and the noted fields' hover. |
| `pages/` | The routes: the landing page, the system selection, the conversation (the interview, `Conversation.tsx`; what it reads and checks before it draws is `conversationHelpers.tsx`, what it reads from the other Systems `crossSystemReaders.ts`, what the Strategy pages read and ask before a change `strategyReaders.ts`, its page moves `pageNavigation.ts`, its export dialogs `ExportFlow.tsx`), the Workbook (`Workbook.tsx`: card notes, review, glossary, references and the business documents; `/glossary`, `/review` and `/documents` open it on their section), the global settings, the generator; and, in development only, the library, the inventory and the looks pages. |
| `framework/parser/`, `model/`, `enums/`, `interview/`, `application/` | The content side with no screen in it: `AnswerParser` reads a System's Markdown (grammar: `framework-dsl-grammar.md`), `model/` holds its types (`FrameworkDocument`, `Section`, `AnswerDefinition`, `TableColumnDefinition`...), `enums/AnswerType`, `InterviewSession`, and the managers of the interview and the review (`InterviewManager`, `ReviewManager`). |
| `framework/engine/` | The rules and the data model, with no screen in them; grouped by subject in `answers/` (reading a System's answers), `export/` (Markdown and PDF), `legal/`, `fields/`, `channels/`, `choices/` (the choice questions of the Ambassador, Purpose, Strategy, Segment, Profile, Competitor and Offering cards), `financial/`, `cards/` (completeness, faces, generated cards), `status/`, `capability/`, `businessFoundation/` and `businessDocuments/`, the rest at its root (a card of choice questions is an engine file, `SegmentQuestions.ts` with `SegmentContext.ts`, or `ProfileQuestions.ts`: the questions, their options and help, when each is asked, the starting values, the settling of answers; the card only draws them): the answers, the cards' completeness, the financial forecast, the generated cards, the exports, the search index, the sources and their Harvard form (`Sources.ts`). Everything a test can say about the content is tested here first. Four large files are folders of topic files, each re-exported from the old file, so every import of the old path stands: `FinancialModel.ts` (`financial/`: period, lists, stored, costs, natures, funding, position, revenue, break even, presenting, an Offering's costs, expected sales, the stress test, what it would take), `AnswerBusinessFoundation.ts` (`businessFoundation/`: Sections 1 and 2, whose channel categories are `channelCategories.ts` and whose readers of a saved answer are `engagementReaders.ts`), `AnswerBusinessCapability.ts` (`capability/`: the types, payment plans, cost options, activity groups, partner groups, responsibilities, an Offering's shares) and `BusinessDocuments.ts` (`businessDocuments/`: reading the Systems, the Canvas, the Plan, the Forecast). |
| `hooks/`, `services/` | The React hooks (`useAutoGrow`, `useListAutoFormat`, `useFloatingPanel`…) and the services that keep state (the organisations, the notes, the preferences, the calendar, the Glossary's terms: `GlossaryService`; `StorageService` saves and loads an interview, and `storageMigrations.ts` brings an interview saved by an earlier version to the current shape; the Organizations themselves are kept in IndexedDB, `IndexedDbStorage.ts`, behind `LocalOrganizationStore`, with the theme, the notes and the preferences still in localStorage). |
| `styles/` | The stylesheets: `tokens/tokens.ts` generates the colours; `cell-focus.css` loads last and holds the global rules (ring, hover, label, underline); `conversation/` and `section-tiles/` are the big sheets split in their load order, each file named by what it mostly holds (the number keeps the order: the cascade depends on it); `tools-menu.css` is the Menu's. A look is a token or a global rule, never a page's own. **Where a class is styled:** `npm run css:where <class>` lists every rule that names it, with file and line (`-- --props` adds what each sets). |
| `library/` | The asset library (contracts, gallery, inventory) and its checks. |
| `data/` | The static lists (`capabilities`, `systems`, the icons, `classifications/`, `glossary`: the app's terms and what they mean) and `examples/`: the two example organisations (the one copy; the app reads it). |
| `assets/` | The Systems' content: `system-answers`, `system-questions`, `system-help` (the Markdown triads), `system-icons`, `capability-icons`, the framework logos and the cursors. |
| `test/`, `docs/` | Test helpers and tests that cross the project (`noEmDash`, `layoutProbe`); `docs/` holds the tests of the documents (`documentReferences`, `documentValues`, `documentAssets`). |

## Rules for a new file

- One component per file; its CSS in the stylesheet of its topic, not in a file of its own, unless it is a control (`back-button.css`).
- A control that two places need is written in `components/controls/` before the second place is written.
- A file over about 1,500 lines is split by card kind or by section before more is added to it.
- The header (`AppHeader.tsx`, `ToolsMenu.tsx`) is drawn on every page, the Landing page first, so it imports only light files: a small helper it needs (`calendar/calendarOpen.ts`, `notepad/useNotepad.ts`, `notepad/WorkbookButton.tsx`) lives in a file of its own, and a panel that reads the engine (the Notes panel, the Calendar's rail) is loaded with `lazy` when it is first drawn. Measured 2026-11-21: the Landing page's first load went from 1,109 KB to 316 KB of JavaScript.
- `docs/README.md` and `docs/index.md` index the documents; `npm run docs:index` rewrites them. The tools are in `tools/scripts/` and `tools/catalogue/`, not in `src`.
