# 10. Documentation System Help

## 01. Folder Structure Help

Folder Structure defines where information actually lives, so anyone can find (or file) a document without guessing.
List your primary folders and what each one is for, then set a few rules for how folders should be created and organized.
Organize by function rather than by team, separating "Customer Support" from "Governance & Compliance," which keeps content easy to locate regardless of who created it.
Getting this right once saves everyone from creating duplicate folders later.

## 02. Metadata Standards Help

Metadata Standards define the small set of descriptive fields every document should carry, so documents can be classified, searched, and trusted.
List the metadata fields you'll use (title, version, status, owner, and similar), the rules for keeping them accurate, and one fully filled-in entry that shows them in practice.
Make your fields specific and useful, including an Owner and a Last Updated date, not just a title and version number.
This is what turns a folder full of files into something searchable and reliable.

## 03. Categories Help

Categories group your documentation by what it actually is, so content stays consistent as more of it gets created.
List your primary categories and set rules for how documents should be assigned to them.
Tie each category to how people actually search, grouping troubleshooting content under "Support Content" rather than mixing it into general documentation.
Keeping categories few and clearly defined is what prevents duplicate or inconsistent filing over time.

## 04. Dictionaries Help

Dictionaries record the key terms your documentation relies on, so everyone means the same thing when they use them.
For each term, provide a clear definition and note how it's actually used.
Define terms that could otherwise be interpreted loosely, like "Archive" and "Documentation Owner," so there's no ambiguity about what they mean in practice.
This matters more as your organization grows and more people are writing documentation independently.

## 05. Naming Conventions Help

Naming Conventions define how files and documents should be named, so everything stays consistent and searchable.
Set clear naming rules, then show the pattern in practice with real filenames, and note any approved exceptions.
Pair each rule directly with a matching filename, like "include version when needed" next to "internal_policy_template_v3," so the rule is unambiguous.
Consistent naming is what prevents confusion when similar documents pile up across different teams.

## 06. Templates Help

Templates give recurring document types a standard structure, so people aren't starting from a blank page every time.
For each template, define its purpose, when it should be used, who owns it, and how often it should be reviewed.
Assign a specific owner and review cadence to each template, like a Compliance Manager reviewing the Policy Template every 24 months, rather than leaving templates unmaintained.
This is what keeps templates useful instead of becoming outdated over time.

## 07. Documentation Rules Help

Documentation Rules set the standards that keep everything above this section working over time: how documents get created, updated, and eventually archived.
Define rules for creating new documents, updating existing ones, and handling documents that are no longer active.
Make rules specific enough to actually follow, like "complete required metadata before publishing," rather than a general call for quality.
Without these rules, even a well-organized system slowly becomes unreliable as it grows.
